## Repository Overview

`@sentio/connect-gateway-es` is a connect-es v2 `Transport` implementation that speaks the
grpc-gateway REST/JSON dialect. At runtime it reads `google.api.http` annotations from
protobuf-es v2 service descriptors (`getOption(method, http)`), builds the HTTP request
(path template substitution, query parameter flattening, body extraction), and maps
responses and errors back into connect semantics (`ConnectError`, NDJSON server streaming).

Key invariants:

- **Browser-first**: no Node-only APIs in `src/` runtime code; `fetch` is injectable.
- **Public APIs only**: depends solely on public exports of `@bufbuild/protobuf` and
  `@connectrpc/connect` (+ `/protocol` subpath). Both are peerDependencies — never move
  them to dependencies (two runtime copies break descriptor identity).
- **No global state**: per-transport configuration only; the route cache is a module-level
  `WeakMap<DescMethod, ...>` keyed by descriptor identity.
- `src/gen/` and `tests/gen/` are generated by `pnpm gen` (buf + protoc-gen-es) and checked
  in; never edit by hand, never post-process. CI verifies they are up to date.
- The strip-imports wrapper (`scripts/protoc-gen-es-strip.mjs`) emulates codegen setups
  that drop options-only imports; route resolution must keep working on those descriptors
  (option bytes survive as unknown fields).

## Commands

```bash
pnpm install
pnpm build            # tsc -> dist/esm
pnpm test             # node:test via tsx (src/**/*.test.ts, tests/unit)
pnpm test:conformance # spawns the Go grpc-gateway echo server (needs go)
pnpm gen              # regenerate src/gen + tests/gen
pnpm lint             # ls-lint + eslint
pnpm format           # prettier
```

## Pull Request Workflow

Always submit changes via PRs — never commit directly to main. Use `git dev <branch-name>`
(defined in `.github/.gitconfig`, registered by `pnpm install`) to create dev branches.
Conventional commits required (`feat(...)`, `fix(...)`, ...) — semantic-release derives
versions from them; `main` publishes `rc` tags, the `release` branch publishes `latest`.

## Layout

- `src/` — library code; one module per concern (route, path-template, transcode,
  query-params, error, stream, http-body, headers, transport).
- `src/gen/google/api/` — vendored descriptors (annotations/http/httpbody) the transport
  needs at runtime.
- `tests/proto/` — kitchen-sink `EchoService` proto exercising every supported
  `google.api.http` feature; also compiled by the Go conformance server.
- `tests/gen/{clean,stripped}/` — the same schemas generated with/without stripped
  google/api imports; route tests must pass against **both**.
- `conformance/` — Go grpc-gateway echo server (own go.mod) mirroring the production mux
  config (`JSONPb{EmitUnpopulated, DiscardUnknown, AllowPartial}`); TS conformance tests
  assert client-encoded requests decode server-side to deep-equal messages.
